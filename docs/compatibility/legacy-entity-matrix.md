## Publication and identity

Entity names and generated IDs pass through ESPHome entity schemas and registration ([components/samsung_ac/__init__.py:603](https://github.com/omerfaruk-aran/esphome_samsung_hvac_bus/blob/6b1966bea8db9344d23763454f9cebed015d15c5/components/samsung_ac/__init__.py#L603), [components/samsung_ac/__init__.py:656](https://github.com/omerfaruk-aran/esphome_samsung_hvac_bus/blob/6b1966bea8db9344d23763454f9cebed015d15c5/components/samsung_ac/__init__.py#L656)). There is no component-specific stable unique-ID override in the inspected device classes. Home Assistant registry identity, restored states, localization and naming across ESPHome upgrades remain UNKNOWN and need integration tests before migration.

Room temperature publication adds the configured offset to both the sensor and climate current temperature ([components/samsung_ac/samsung_ac_device.h:244](https://github.com/omerfaruk-aran/esphome_samsung_hvac_bus/blob/6b1966bea8db9344d23763454f9cebed015d15c5/components/samsung_ac/samsung_ac_device.h#L244)). Custom numeric sensors publish values; custom binary sensors use `value != 0` ([components/samsung_ac/samsung_ac_device.h:224](https://github.com/omerfaruk-aran/esphome_samsung_hvac_bus/blob/6b1966bea8db9344d23763454f9cebed015d15c5/components/samsung_ac/samsung_ac_device.h#L224)). Target/mode/power setters update their associated entities; command callbacks build a ProtocolRequest. Exact availability, optimistic state and error behavior need fixture-based comparison.

Swing Off/Horizontal/Vertical/Both depends on configured capabilities.
